# REVIEW.md

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `health` | Returns `{"status":"ok"}` without checking MongoDB; should return 503 if the DB is unreachable | Runner polls `/health` before seeding — a dead DB passes silently | Added `db.command("ping")` in a try/except; raises 503 on failure |
| 2 | `create_employee` L82 | `datetime.now()` creates a naive (no-timezone) datetime; stored in MongoDB as local wall-clock time | `created_at` returned as a wrong epoch-ms value in non-UTC timezones | Changed to `datetime.now(timezone.utc)` |
| 3 | `create_employee` / `list_employees` | `created_at` is a Python `datetime` returned raw; the contract requires epoch **milliseconds** | Response fails schema validation; any time field is a datetime string instead of an integer | Added `serialize_employee()` helper that converts all datetime fields to `to_ms()` |
| 4 | `list_employees` L94 | `count_documents({})` always counts the whole collection; ignores the `department` filter | `total` is wrong when `department` is supplied | Changed to `count_documents(q)` |
| 5 | `list_employees` L96 | `skip = page * page_size` — page 1 skips the first 20 records | Calling `GET /employees?page=1` returns the second page, not the first | Changed to `(page - 1) * page_size`; also added `.sort("emp_code", ASCENDING)` (contract requires sorted output) |
| 6 | `punch_in` L101 | `emp` can be `None` (unknown employee) but is used on line 113 without a null check | Punching in with a non-existent `emp_code` raises an unhandled `TypeError` instead of 404 | Added `if not emp: raise HTTPException(404, ...)` immediately after `find_one` |
| 7 | `punch_in` L102-103 | `datetime.fromtimestamp()` produces a naive local-time datetime; `ts.date()` returns the local OS date, not the IST attendance date | Punch-in at 00:05 IST (18:35 UTC previous day on a UTC server) creates a record for the wrong date; overnight-shift date logic is entirely absent | Changed to `from_ms()` (timezone-aware UTC); compute attendance date with `get_attendance_date()` which applies R1 IST + overnight logic |
| 8 | `punch_in` L104 | Existence check uses `find_one` + `insert_one` (check-then-insert) — not atomic | Two simultaneous punch-ins for the same employee/date both pass the check and both insert, creating duplicate records | Removed the pre-check. Rely on the unique index on `(emp_code, date)` and catch `DuplicateKeyError` on insert |
| 9 | `compute_late_minutes` L36-37 | `punch_in.replace(hour=h, minute=m, ...)` uses the naive local datetime's date for `start`; grace-period check is `minutes > 10` (compares whole minutes) meaning 10 min 59 sec is incorrectly let through | 09:40:59 IST → 0 late (should be 10 late minutes per R2); also breaks in any non-IST server timezone | Convert `punch_in` to IST, truncate to seconds, compare elapsed **seconds** strictly `> 600`, return `elapsed_seconds // 60` |
| 10 | `compute_overtime` L46 | `datetime.fromisoformat(date_str).replace(hour=h, minute=m, tzinfo=IST)` builds shift_end on the **attendance date** even for overnight shifts; for a 22:00–06:00 shift the end is the *next* calendar day | Overnight-shift overtime is always negative → 0, even if the employee left 40 min late | Detect overnight (`shift_end <= shift_start`); if so, build `end` on `att_date + 1 day`; compare elapsed seconds `>= 1800` (R3) |
| 11 | `list_attendance` L144-150 | Fetches the **entire** collection into Python, then sorts and paginates in memory | On the grader's 100k-record dataset this is an OOM/timeout; also total is `len(docs)` (filtered but all loaded) | Pushed sort `[("date", DESCENDING), ("emp_code", ASCENDING)]`, skip, and limit to MongoDB; count with `count_documents(q)` |
| 12 | `punch_in` response | `punch_in` datetime and any other datetime fields are returned as Python objects (serialized as ISO strings by FastAPI), not epoch milliseconds | Response body fails the `EpochMillis` schema check; grader cannot parse times | Applied `serialize_record()` to the response doc |

**Not a defect:** The `IST` constant (`timezone(timedelta(hours=5, minutes=30))`) is correct and reused throughout. The `compute_work_hours` helper's division and `round()` call looked suspicious but the real issue is Python's banker's rounding — fixed via `round_half_up()` using `Decimal` + `ROUND_HALF_UP`.
